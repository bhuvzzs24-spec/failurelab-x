# Research engine and model boundary

“AI” here comprises bounded adaptive planning and optional constrained model suggestions. No LLM is needed to run the algorithms. Invariant truth is always deterministic typed evaluation of authoritative observations.

Random, coverage and cost-normalized ridge linear UCB explore the same finite candidate catalogue. UCB features include defect/fault/timing/concurrency and registered graph/invariant relevance; alpha=1.4. Novel signatures earn reward 1, repeats 0. Acquisition uncertainty is not calibrated confidence. Benchmark cohorts start with no history and never ingest held-out evaluation results.

Repeated ddmin removes action subsets, then searches a finite timing/input/concurrency lattice. It accepts only repeated exact-signature reproductions. A budget-limited result can be useful without proving local minimality; unknown neighbors never prove minimality. Causal investigation introduces/removes competing mechanisms in paired fresh namespaces, retaining assumptions and concrete trial IDs. Mechanism support does not identify unique causal source lines.

Repair permits only a literal `POLICIES` map with six known boolean keys. AST validation rejects imports, calls, other statements/paths and arbitrary code. Candidate workspaces are separate from runtime source. Independent verifier execution is a fixed Docker image with matching original/candidate scenarios, no external network, bounded CPU/memory/PIDs, nonroot user and hard deadlines. There is no unrestricted repository editing, automatic merging or production patch deployment.

Optional local Ollama may propose schema-constrained hypotheses/policies. Set OLLAMA_URL and OLLAMA_MODEL in the private worker environment; the model service must be operator-managed/allowlisted. Unknown evidence IDs and unsupported policies are rejected. Suggestions cannot mark hypotheses supported or set invariant/verification truth. No model was available for the final measured run; deterministic planning/interventions/repair preparation remain functional. See `docs/PHASE3.md` for algorithm references and exact limitations.

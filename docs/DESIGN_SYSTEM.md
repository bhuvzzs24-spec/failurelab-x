# FailureLab X product design

The existing application is retained: typed backend clients, TanStack Query caches, role-aware mutations and all research engines remain the source of truth. `frontend/src/app/premium.css` layers a coherent visual system over the established component contracts.

Tokens use charcoal/navy foundations (`#0c0e14`), layered surfaces, restrained violet (`#ada7ff`) and blue (`#82b8ff`), distinct semantic outcome colors, consistent panel radii, readable supporting labels and visible keyboard focus. Reduced-motion preferences disable nonessential transitions. Navigation groups follow observation, discovery, investigation and workspace tasks; project selection and real backend readiness stay in the global header.

The command center combines an actual metric rail, prominent interactive topology, research job counts, recorded outcome chart, recent runs and findings. Graph nodes represent registered services only. Auto-layout, fit, filtering, drag/pan, keyboard inspection and evidence links work on backend graph data; edges do not imply live traffic or health.

Experiment Studio uses five steps with per-step validation, registered target/invariant review, explicit fault confirmation and real execution monitoring. Read-only access still allows definition inspection and prevents mutation. Historical job status never substitutes for a successful invariant or verification outcome.

The causal workspace uses keyboard-accessible hypothesis tabs, paired intervention outcomes and retrievable trial evidence. Supporting and contradicting observations remain distinct, and a supported tested mechanism is not presented as a proven unique root cause. Adaptive search displays recorded decision history and measured comparison bars, including underperformance. Minimization compares original/reduced action sequences with attempt counts and uncertainty. Replay uses persisted timestamps and event filters, not a generated request animation.

Verification retains actual code diffs, independent scenario outcomes, regression matrices and infrastructure failures. Candidate preparation clearly states that syntax/literal validation is not execution. Evidence adds safe highlighted JSON, artifact-category search, metadata/integrity views, copy/download and recorded chronology. All untrusted strings are rendered as React text; no raw HTML insertion is used.

Desktop and mobile layouts are tested against real records. Axe checks cover all 13 workspace routes; existing tests exercise dialogs, keyboard navigation, API errors, real fault execution, cancellation and private/read-only boundaries. Screenshots are captured from that production build, never from fabricated data fixtures.
